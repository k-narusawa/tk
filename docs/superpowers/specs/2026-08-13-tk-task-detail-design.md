# tk: タスクに詳細メモを持たせる

2026-08-13

## 背景

タスクは `- [ ] タイトル @tag` の1行しか持てない。右ペインに出るのも
タイトル・tag・state だけで、「なぜこのタスクがあるのか」「どこまで調べたか」を
書く場所がない。複数行の自由メモを書けるようにする。

書くのは Neovim。tk 自身はエディタを持たない。

## 保存形式

チェックボックス行の**直後に続くインデントされた行**を、そのタスクの詳細とする。

```markdown
- [ ] 認証まわりのリファクタ @today
  - Cookie の SameSite を Lax に
  - 参考: https://example.com/rfc

  RFC を読み直すこと
- [ ] 別のタスク
```

判定規則:

- チェックボックス行の次の行から、**インデントされた非空行**または**空行**が
  続く限りを詳細とする
- 非インデントの非空行（`## メモ` など）、または次のチェックボックス行で終了
- 末尾の空行は捨てる
- `  - [ ] サブタスク` のようなインデントされたチェックボックス行は、
  **今まで通り独立したタスク**として扱う。既存の挙動を変えない

空行を詳細に含めるのは、メモが複数段落になるのが自然だから。末尾の空行を
捨てるので、「タスクの後に空行があって次が `## メモ`」という既存ファイルの
詳細は空のままになる。

別ファイル（`~/.tk/notes/<id>.md`）に持つ案は却下した。`ID` が
`task:<行番号>` なので、行がずれた瞬間にメモが別のタスクに付く。

## 編集フロー

`e` を押すと `$EDITOR +<行番号> <tasks.md>` が起動する。閉じたら
`tasks.md` を読み直す。**tk は詳細を書き込まない。**

一時ファイルに詳細だけを抜き出して編集させ、tk が該当行範囲に書き戻す案は
却下した。行範囲の置換ロジックと外部変更検知が必要になり、コード量が
3倍以上になる。それに見合う利点がない。

`tea.ExecProcess` で端末を明け渡す形は `d`（`gh pr diff`）と `a`（AI CLI）で
既に使っている。同じ仕組みをそのまま使う。

エディタは `TK_EDITOR` → `$VISUAL` → `$EDITOR` → `vi` の順で決める。
`TK_EDITOR` を先頭に置くのは、`TK_TASKS_FILE` / `TK_AI_CMD` と同じ
「tk のときだけ別のものを使いたい」逃げ道。

`+<行番号>` は vi 系の記法。`nvim` / `vim` / `vi` / `emacs` で通る。
それ以外のエディタを使う場合は行ジャンプが効かないか、引数が無視される。
`ID` は 0 始まりの行番号、エディタの `+N` は 1 始まりなので **+1 する**。

PR にカーソルがあるときの `e` は何もしない。

## 画面

一覧には印を付けない。詳細の有無はカーソルを合わせれば右ペインで分かるし、
一覧の1文字は狭い端末で先に削られる場所でもある。

右ペインは `state` の下に空行を1つ挟んで詳細をそのまま出す。
インデントは剥がす（枠の中で二重にインデントされて見えるため）。

```
╭─タスク (4)─────────╮╭─────────────────────────╮
│> □ 認証リファクタ  ││ 認証リファクタ          │
│  □ 資料作成        ││                         │
│  ▣ レビュー        ││ tag    : @today         │
│  □ 予約            ││ state  : 未完了         │
╰────────────────────╯│                         │
╭─GitHub (3)─────────╮│ - Cookie の SameSite    │
│                    ││ - 参考: https://...     │
╰────────────────────╯╰─────────────────────────╯
 h/l:ペイン j/k:移動 space:完了 n:追加 e:編集 enter:開く d:diff a/A:AI r:更新 R:再読込 q:終了
```

## 実装

### `internal/domain`

- `Item` に `Body string` を追加（`Tag` と同じく KindTask のみ）。
  `[]string` にしない。`Item` は `==` で比較しているテストがあり、
  スライスを持たせると比較不能になる
- `task` に `body []string`、`Parse` で収集する
- `Toggle` / `Render` は無変更。詳細行は「解釈しない行」のまま原文で残るので、
  `Parse` → `Render` のバイト一致は保たれる
- **`Add` を直す。** 今は「最後のチェックボックス行の直後」に挿入するので、
  詳細行があると**メモの途中に新しいタスクが割り込む**。
  「最後のタスクの詳細の末尾の直後」に変える

### `internal/adapter/editor`（新規）

```go
func Command(editorCmd, path string, line int) (*exec.Cmd, error)
```

`ai.Command` と同じく `*exec.Cmd` を返すだけ。`tea.ExecProcess` で包むのは
`internal/adapter/tui` の仕事。`editorCmd` は `strings.Fields` で分割する
（`"code -w"` のような指定を通すため）。空なら error。

### `internal/adapter/tui`

- `Model` に `tasksFile` と `editorCmd` を持たせる
- `e`: タスクにカーソルがあるときだけエディタを起動し、`execDoneMsg` で
  戻ったら `reloadTasks()` する
- `detailText` に詳細を出す
- `help` に `e:編集` を追加

### `main.go`

`editorCommand()` を足し、`tasksPath()` の結果と一緒に `tui.New` へ渡す。

## テスト

- domain: 詳細の収集（インデント / 空行を含む / 非インデントで終了 /
  次のチェックボックスで終了 / 末尾空行の切り捨て / ネストしたチェックボックスは
  別タスクのまま）、round-trip の維持、`Add` が詳細の後ろに入ること
- editor: `+<行番号>` の組み立て（0 始まり → 1 始まりの変換）、
  `strings.Fields` による分割、空文字列でエラー
- tui: `e` がタスクでは非 nil、PR では nil を返すこと

## やらないこと

- 一覧に詳細ありの印を付ける
- tk の中での編集（textarea）
- 詳細の全文検索
- 詳細を AI CLI に渡す（`a` / `A` はタイトルのみのまま。端末の外へ出る
  データが増えるので、必要になってから別途決める）
