# tk: タブを lazygit 風の上下ペインに変える

2026-08-13

## 背景

いまはタスクと GitHub が「タブ」で、`[` / `]` でどちらか一方だけを表示している。
もう一方の状態（PR が何件来ているか）が見えないので、タブを切り替えるまで
気づけない。lazygit のように両方を常時出し、フォーカスだけを移す形にする。

## 画面

```
╭─タスク (4)─────────╮╭─────────────────────────╮   ← タスクにフォーカス中（緑）
│> □ 買い物          ││ □ 買い物                │
│  □ 資料作成        ││                         │
│  ▣ レビュー        ││ tag   : home            │
│  □ 予約            ││ state : 未完了          │
╰────────────────────╯│                         │
╭─GitHub (3)─────────╮│                         │
│                    ││                         │
╰────────────────────╯╰─────────────────────────╯
 h/l:ペイン j/k:移動 space:完了 n:追加 enter:開く d:diff a/A:AI r:更新 R:再読込 q:終了
```

- 画面最上部のタブ行は削除する。枠のタイトルがその役目を兼ねる。
- 左カラムはアコーディオン。フォーカス中の枠が残りの高さを全部使い、
  非フォーカスの枠は高さ 3（枠線と空の1行）に潰れる。
- 右の詳細ペインに枠タイトルは付けない。中身を見れば何かは分かる。
- 潰れた枠は中身が一切見えないので、**タイトルに件数を出す**。
  これが無いと「PR が来ているかどうか」が分からず、常時表示にした意味が消える。
  ただし PR の取得が終わるまでは `GitHub (…)` とする。取得中の `(0)` は
  「PR なし」と区別が付かず、件数を出す意味が反転する。
- 幅が足りず件数が入らないときは、件数を落として名前だけ残す。
- 右の詳細ペインはフォーカス中ペインの選択アイテムを映す。フォーカスは持たない。
- フォーカス中の枠は緑（ANSI の 2 番。実際の色は端末のテーマに従う）にする。
  当初は枠の大小だけで足りると考えたが、一覧が空のときに区別が付かなかった。
  色を使うのはここだけ。

## キー

| キー | 変更 |
|---|---|
| `h` / `l` | **新規**。左2枠のフォーカスを循環する。ペインは2つなので、どちらのキーでも「もう一方」へ移る |
| `[` / `]` | **削除** |
| `j` `k` `space` `n` `enter` `d` `a` `A` `r` | 「現在のタブ」を「フォーカス中ペイン」に読み替える。挙動は変えない |
| `R` `ctrl+d` `ctrl+u` `q` | 変更なし |

カーソルはペインごとに独立して保持する（既存のタブと同じ）。

## 実装

### Model（`internal/adapter/tui/model.go`）

`tabID` / `tabTask` / `tabGitHub` を `paneID` / `paneTasks` / `paneGitHub` に改名する。
UI からタブという概念が消えるため。

状態は既存の `cursor` / `otherCursor`（非表示側のカーソル退避）の形をそのまま
踏襲し、リストにも同じ対を持たせる:

```go
focus       paneID
items       []domain.Item // フォーカス中ペインの一覧
cursor      int
otherItems  []domain.Item // 非フォーカスペインの一覧
otherCursor int
```

`[paneCount]` の配列に持ち替える案もあったが、`items` / `cursor` を参照して
いる箇所が広く、既存の `otherCursor` と非対称な形が2つ並ぶだけになるので採らない。
`otherItems` は潰れた枠の件数表示にしか使わない。

`reload()` は両方のリストを取り直す（`Tasks()` も `PRs()` も usecase 内の
キャッシュを読むだけなので追加の I/O は無い）。`switchTab` は
`focusPane` に改名し、中身は今と同じくカーソルを退避して入れ替える。

usecase 層と domain 層は変更しない。

### レイアウト（`internal/adapter/tui/view.go`）

寸法の計算が `View` と `WindowSizeMsg` の2箇所にある（README に
「片方だけ直すと右ペインが枠から溢れる」と明記されている既知の罠）。
枠が1つ増えて値も増えるので、`layout` 構造体と `newLayout(w, h)` に
切り出して両方から呼ぶ。

```go
type layout struct {
	left, right        int // 枠込みの幅
	body               int // 右ペイン / 左カラム全体の高さ
	focused, collapsed int // 左カラム2枠それぞれの高さ（合計 = body）
}
```

- `collapsed` は 3 固定、`focused = body - collapsed`。`box.Height` は最小値
  なので、空文字を描いても内側に1行は残る。2 にすると枠が勝手に伸びて下の枠を
  押し出す。
- `body` はフッタ1行を除いた `height-1`。旧実装は `height-5` にタブ行と
  フッタを足して `height-3` しか使っておらず、3行を空けたままだった。
  アコーディオンで広げた枠がそのぶん損をするので、ここで使い切る。
- `body` の下限は 6（潰れた枠2つぶん）。これを割る端末では枠が入らないので、
  `View` が本文を末尾から削る。**削ってもフッタは必ず残す** —
  保存失敗や `gh` のエラーが見えなくなるほうが困る。

### 枠の中身を切り詰める

`box.Height` / `Width` が最小値である以上、枠に収める責任は中身の側にある。
枠が1つだったころは上下の余白が誤差を吸収していたが、2つ縦に並ぶと下の枠が
押し出されて即座に崩れる。`listView` を2点直す:

- 末尾に改行を付けない（`rows` 行のつもりが `rows+1` 行になっていた）
- 各行を枠の内幅で切り詰める（PR のタイトルは平気で枠幅を超え、折り返すと
  1件が2行になる）

### 枠タイトル

lipgloss v2.0.5 に枠タイトルの API は無い。上辺だけ自前で組んで、描画済みの
箱の1行目と差し替える:

```go
// titles は長いものから順に渡す。収まらなければ次を試す。
func withTitle(box string, style lipgloss.Style, titles ...string) string
```

- 罫線の文字は `lipgloss.RoundedBorder()` から取る。直書きすると、箱の側面と
  上辺で別の文字を使う箱が黙って出来上がる。
- タイトルには全角文字が入るので、削る罫線の本数は `len([]rune)` ではなく
  `lipgloss.Width(title)` で数える。
- 上辺の幅は指定値ではなく**描画済みの1行目**から測る。`Style.Width` は下限で
  あって、狭い端末では指定より広い箱が返ってくる。
- 色を付けると1行目がエスケープ列を含む。だから描画済みの文字列を rune 単位で
  切り貼りはしない（`lipgloss.Width` はエスケープ列を無視して数えてくれる）。

## テスト

既存の方針（「端末の幅・高さに収まる」形で書く）を維持する。追加するのは:

- 左カラム2枠の高さの合計が右ペインと一致すること。**レンダリング結果から
  枠の閉じ位置を探す形にはしない** — 左カラムが伸びても最終行は
  「左の下端 ++ 右の下端」のままで、目印が同じ行に居続けて検出できない。
  `paneView` / `detailView` を直接測る。
- 端末の高さを使い切ること、および高さが足りないときもフッタが残ること
- `h` / `l` の循環と、カーソルがペインごとに保持されること
- 枠のタイトル: 件数、取得中の `(…)`、幅が足りないときの名前だけの表示
- フォーカス中の枠が色付きであること。上辺は自前で組んでいるので、
  **上辺以外の枠線も**見る（片方だけ色が付く実装を通してしまう）
- フォーカス中ペインでしか効かないキー（`n` は GitHub 枠で無効、
  `d` はタスク枠で無効）

既存テストの `[` / `]` は `h` / `l` に置き換える。「同じタブへ切り替えても
カーソルが動かない」テストは、循環するようになって前提が消えるため削除する。

## やらないこと

- 詳細ペインへのフォーカス移動（スクロールは今まで通り `ctrl+d` / `ctrl+u`）
- ペインの色分け・境界のドラッグリサイズ
- 3つ目のペインを見越した一般化
